Enjab Auth is the central login for every Enjab tool. Hand this page to a coding agent
and it can add login + access control to an Enjab service.

- **Issuer:** `https://auth.enjab.ae`
- **Discovery:** `https://auth.enjab.ae/.well-known/openid-configuration`
- It is **OAuth 2.0** (authorization-code flow), with one convenience: the token
  response also returns the user's profile, so you usually need no extra call.

## What Enjab does (and what you must not)

- It handles **all** authentication: passwords, two-factor (TOTP), sessions, lockout.
  Your tool never sees a password or a 2FA code and never builds a login screen.
- It handles **authorization at the door**: a user can finish "Sign in with Enjab" for
  your tool only if an admin gave them access. If they can't, Enjab shows a "no access"
  screen and never returns to your tool.
- It shows the user a greeting + consent screen, then sends them back to you. Your tool
  does not build this.
- **Sign-out is confirmed by Enjab and per-tool.** Your "Sign out" button just navigates
  to your `/api/auth/logout` route; Enjab shows a confirm page, and confirming drops only
  your tool, never the central session. Never call a sign-out or clear the session
  yourself.

<Callout type="warn" title="Re-validate every request">
On each request, read the user with `getUser()`, which calls `/userinfo` fresh
(`cache: "no-store"`). Do **not** cache the user object beyond the request or trust your
cookie's claims. This is the only way central sign-out, account disable, and role
changes reach your tool. If you cache the user, a signed-out or disabled person keeps
working.
</Callout>

## The user object you receive

```json
{
  "sub": "0f3c...",            // stable Enjab user id — your foreign key for this user
  "email": "sara@enjab.ae",
  "name": "Sara Ahmed",        // set in Enjab admin — greet them with it
  "roles": ["reception"],      // ONLY present if your tool is role-aware; otherwise omitted
  "is_super_admin": false,     // ONLY present if your tool is role-aware; otherwise omitted
  "is_active": true
}
```

Most tools never see `roles` or `is_super_admin` (the keys are absent) and must not
branch on them. **Access is binary:** if Enjab let the user in, that is the whole
decision — do not gate features by role. Turn roles on only when your tool has functions
not every authorized user should reach; then an admin flips your tool to "role-aware" and
the `user` object starts including `roles`.

## Register your tool (one time, done by an admin)

<Steps>

<Step>
### Add the tool
In [auth.enjab.ae/admin/apps](https://auth.enjab.ae) → **Add tool**, enter the name,
slug, and domain. The domain **must** be on `enjab.ae`.
</Step>

<Step>
### Copy the credentials
Copy the generated `ENJAB_CLIENT_ID` and `ENJAB_CLIENT_SECRET` (the secret is shown
once).
</Step>

<Step>
### Confirm the redirect URI
Make sure the redirect URI matches your callback exactly — default
`https://<your-domain>/api/auth/callback`. The host is locked to the tool's domain; you
choose the path.
</Step>

<Step>
### Create roles (optional)
In [auth.enjab.ae/admin/roles](https://auth.enjab.ae), attach this tool to the roles that
should reach it, and assign those roles to people.
</Step>

</Steps>

## Environment variables

```bash
ENJAB_CLIENT_ID=enjci_...
ENJAB_CLIENT_SECRET=enjsk_...        # SERVER ONLY. Never ship to the browser.
ENJAB_REDIRECT_URI=https://yourtool.enjab.ae/api/auth/callback
ENJAB_ISSUER=https://auth.enjab.ae
```

## The flow

1. A signed-out user hits your tool. You redirect them **immediately** (no button, no
   login page of your own) to
   `https://auth.enjab.ae/authorize?client_id=...&redirect_uri=...&response_type=code&state=<return-path>`.
2. Enjab signs them in (password + 2FA) if needed, checks they may open your tool, then
   redirects to your `redirect_uri?code=<one-time-code>&state=<return-path>`.
3. Your **server** calls `POST https://auth.enjab.ae/api/oauth/token` with the code + your
   client secret. You get back `{ access_token, user }`.
4. You store the `access_token` in your own httpOnly cookie and let the user in.
5. On later requests, read the user via
   `GET https://auth.enjab.ae/api/oauth/userinfo` with `Authorization: Bearer
   <access_token>` — always fresh, so a revoked role takes effect right away.

<Callout title="No login button">
Do not build a "Sign in with Enjab" button or any login screen. The moment a signed-out
user touches any page, your middleware redirects them straight to `/authorize`. Enjab
owns the entire login + greeting experience.
</Callout>

## Drop-in reference (Next.js App Router)

```ts title="lib/enjab-auth.ts"
import "server-only";
import { cookies } from "next/headers";
import { cache } from "react";

const ISSUER = process.env.ENJAB_ISSUER ?? "https://auth.enjab.ae";
export const SESSION_COOKIE = "enjab_session";

export type EnjabUser = {
  sub: string; email: string; name: string;
  roles?: string[];          // present only if the tool is role-aware
  is_super_admin?: boolean;  // present only if the tool is role-aware
  is_active: boolean;
};

export function loginUrl(returnPath = "/") {
  const u = new URL(ISSUER + "/authorize");
  u.searchParams.set("client_id", process.env.ENJAB_CLIENT_ID!);
  u.searchParams.set("redirect_uri", process.env.ENJAB_REDIRECT_URI!);
  u.searchParams.set("response_type", "code");
  u.searchParams.set("state", returnPath);
  return u.toString();
}

// Cached per request. Returns null if signed out or the token is no longer valid.
export const getUser = cache(async (): Promise<EnjabUser | null> => {
  const token = (await cookies()).get(SESSION_COOKIE)?.value;
  if (!token) return null;
  const res = await fetch(ISSUER + "/api/oauth/userinfo", {
    headers: { Authorization: `Bearer ${token}` },
    cache: "no-store",
  });
  return res.ok ? ((await res.json()) as EnjabUser) : null;
});

export async function exchangeCode(code: string): Promise<string | null> {
  const res = await fetch(ISSUER + "/api/oauth/token", {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: new URLSearchParams({
      grant_type: "authorization_code",
      code,
      redirect_uri: process.env.ENJAB_REDIRECT_URI!,
      client_id: process.env.ENJAB_CLIENT_ID!,
      client_secret: process.env.ENJAB_CLIENT_SECRET!,
    }),
    cache: "no-store",
  });
  if (!res.ok) return null;
  return (await res.json()).access_token as string;
}
```

```ts title="app/api/auth/callback/route.ts"
import { NextResponse, type NextRequest } from "next/server";
import { exchangeCode, SESSION_COOKIE } from "@/lib/enjab-auth";

export async function GET(req: NextRequest) {
  const code = req.nextUrl.searchParams.get("code");
  const state = req.nextUrl.searchParams.get("state") || "/";
  if (!code) return NextResponse.redirect(new URL("/", req.url));
  const token = await exchangeCode(code);
  if (!token) return NextResponse.redirect(new URL("/", req.url));
  // Only ever return to a local path.
  const dest = state.startsWith("/") && !state.startsWith("//") ? state : "/";
  const res = NextResponse.redirect(new URL(dest, req.url));
  res.cookies.set(SESSION_COOKIE, token, {
    httpOnly: true, secure: true, sameSite: "lax", path: "/", maxAge: 60 * 60 * 8,
  });
  return res;
}
```

```ts title="app/api/auth/logout/route.ts"
import { NextResponse, type NextRequest } from "next/server";
import { SESSION_COOKIE } from "@/lib/enjab-auth";

const ISSUER = process.env.ENJAB_ISSUER ?? "https://auth.enjab.ae";

// Sign-out ALWAYS goes through Enjab's confirm page first, and clears ONLY this tool's
// session. Do NOT clear the cookie before ?confirmed=1, or you skip the confirmation.
export async function GET(req: NextRequest) {
  if (req.nextUrl.searchParams.get("confirmed") === "1") {
    const res = NextResponse.redirect(`${ISSUER}/logged-out?client_id=${process.env.ENJAB_CLIENT_ID}`);
    res.cookies.delete(SESSION_COOKIE);
    return res;
  }
  return NextResponse.redirect(`${ISSUER}/logout?client_id=${process.env.ENJAB_CLIENT_ID}`);
}
```

```ts title="proxy.ts"
// Next 16 middleware — sends signed-out users straight to Enjab.
import { NextResponse, type NextRequest } from "next/server";

const ISSUER = process.env.ENJAB_ISSUER ?? "https://auth.enjab.ae";

export function proxy(req: NextRequest) {
  const { pathname } = req.nextUrl;
  if (pathname.startsWith("/api/auth")) return NextResponse.next(); // callback/logout are public
  if (req.cookies.has("enjab_session")) return NextResponse.next();

  const u = new URL(ISSUER + "/authorize");
  u.searchParams.set("client_id", process.env.ENJAB_CLIENT_ID!);
  u.searchParams.set("redirect_uri", process.env.ENJAB_REDIRECT_URI!);
  u.searchParams.set("response_type", "code");
  u.searchParams.set("state", pathname);
  return NextResponse.redirect(u);
}

export const config = {
  matcher: ["/((?!_next/static|_next/image|favicon.ico|.*\\..*).*)"],
};
```

### Use it in a page

```tsx
import { redirect } from "next/navigation";
import { getUser, loginUrl } from "@/lib/enjab-auth";

export default async function Page() {
  const user = await getUser();
  if (!user) redirect(loginUrl("/"));   // token expired between requests
  // Most tools stop here: being signed in IS the authorization.
  return <p>Hello {user.name} ({user.email})</p>;
}

// ONLY if your tool is role-aware, gate an internal function:
//   if (!user.roles?.includes("reception") && !user.is_super_admin) {

//   }
```

## Other stacks (no framework)

Same three calls: redirect to `/authorize`, then **server-side** `POST /api/oauth/token`
with your client secret to get `{ access_token, user }`, then `GET /api/oauth/userinfo`
with the bearer token whenever you need a fresh user. Keep the access token in a secure,
httpOnly, server-set cookie. Never put the client secret in client code.

## Security rules (do not skip)

- The **client secret is server only**. If it ever reaches the browser, rotate it from
  the tool's page in Enjab Auth admin.
- Your `redirect_uri` must be **https on an `enjab.ae` domain** and registered in Enjab.
  Enjab refuses to send a code anywhere else — that is what stops a random site from
  harvesting a login.
- Store the access token in an httpOnly + secure + sameSite cookie.
- Trust `sub` as the user's identity. Never trust anything the browser claims about who
  the user is — always derive it from `getUser()` / `/userinfo`.
